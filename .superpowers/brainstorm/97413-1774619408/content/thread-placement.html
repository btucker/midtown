Where should threads live in the sidebar?

Same threads, three different placements. Which helps you stay focused?

A

Under Channels (current)

Threads nested below their parent channel

Channels
# auth-refactor
⌇ token refresh logic
# api-redesign
⌇ pagination approach
⌇ error response format
# mobile-perf
# ci-fixes

Pros

  • Clear parent relationship

Cons

  • Makes channel list long & hard to scan
  • Threads mixed with navigation
B

Own Section

Threads in a dedicated section between Tasks and Channels

Tasks 3
refactor auth middleware
fix mobile scroll perf
Threads 3
token refresh logic #auth
pagination approach #api
error response format #api
Channels
# auth-refactor
# api-redesign
# mobile-perf
# ci-fixes

Pros

  • Threads are their own thing — easy to scan
  • Channel list stays clean
  • Channel tag gives context without nesting

Cons

  • More sections in sidebar
  • Thread/task relationship not visible
C

Merged with Tasks

Threads grouped under their related task — one "Active Work" section

Active Work 3
refactor auth middleware #auth
45%
💬 token refresh logic
fix mobile scroll perf #mobile
22%
Standalone threads
💬 pagination approach #api
💬 error response format #api
Channels
# auth-refactor
# api-redesign
# mobile-perf
# ci-fixes

Pros

  • Shows thread ↔ task relationship
  • One "here's your work" section
  • Channel list is pure navigation

Cons

  • Threads without a task need a fallback
  • More complex component
